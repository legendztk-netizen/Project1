# Spec 11：产品条目级发布、产品管理与总成管理重构

> 状态：Completed（本地范围，2026-09-14 复核关闭）。本轮按用户确认仅交付本地，远程部署另行验收。
> 验收记录：[Spec 11 本地验收](../operations/spec-11-local-acceptance.md)。原需求于 2026-09-08 确认。技术栈保持 TypeScript、React Router、
> Cloudflare Workers、D1 与 R2。本 Spec 扩展并部分取代 Spec 8 和 Spec 9；
> 已确认 Draft 差异转独立待审核请求、原币种多币种价格和既有 Dash 匹配边界。

## 一、问题说明

现有产品维护流程以完整 Catalog Draft 和完整 Catalog Release 为发布单位。
即使管理员只新增或修改一个系列、一个 SKU 或一个价格，也需要进入共享 Draft，
再执行目录审核、总成更新和整本目录发布。该模型造成以下问题：

- 手动新增一个产品仍需要经过与 Excel 批量导入相同的审核和整本发布流程；
- 多个不相关的手动修改和 Excel 导入可能进入同一个共享 Draft；
- 产品参数、价格和总成兼容关系的更新时间与责任边界不清晰；
- 产品审核页面展示完整目录，而不是本次 Excel 导入形成的待审核条目；
- 产品维护列表缺少系列与子体的分层管理、批量选择、条件删除和完整编辑入口；
- 自动生成的总成关系缺少可持续生效的手动新增、停用和启用规则；
- 单条更新依赖整本 Catalog Release，无法直接表达“后发布的单条修改覆盖先发布修改”。

## 二、目标

1. 将产品维护和发布的业务单位从“整本目录版本”改为“单个系列或单个 SKU 的修订版本”。
2. 手动新增或编辑不进入 Excel 审核队列；有权限的维护人员可直接发布。
3. Excel 导入后拆分为可独立选择、批准、拒绝或删除的系列与 SKU 更新请求。
4. 将所有产品集中到“管理所有产品”，按系列与子体两级展示和维护。
5. 将兼容关系和衍生总成操作集中到“总成管理”。
6. 允许产品发布与总成更新分开进行，同时阻止未更新的受影响组合进入客户配置器。
7. 保留历史目录、报价、RFQ、图片版本和审计记录的可追溯性。

## 三、非目标

- 不迁移到 Java、Spring Boot 或 PostgreSQL。
- 不增加新的产品技术参数；商业字段按本 Spec 的多币种与包装适用性规则调整。
- 不增加第二人审核或生产验证流程。
- 不区分 Excel 导入权限与 Excel 审核权限。
- 不把长度、Clocking、保护方案或客户应用条件加入总成 SKU。
- 不让系统提前生成装配服务费、保护金额或客户成品总成价格。
- 不修改历史报价、RFQ、PI、订单或已保存业务快照中的原始数据。
- 不将 Cost Basis 变成产品发布必填项或客户可见字段。
- 不提供自动换汇、实时汇率源或同一 SKU 同时生效的多个币种价目表。
- 不把压力、温度、扣除量新增为总成待更新触发条件，也不新增相应的校验流程。

## 四、保留的技术与数据边界

- React Router 继续承载前台和后台页面。
- Cloudflare Workers 继续承载服务端业务逻辑。
- D1 继续作为产品、总成、审核请求和审计数据的数据源。
- R2 继续保存产品图片及其他二进制文件。
- Drizzle/SQL 迁移继续管理数据库结构。
- Spec 9 已确认的中英文产品参数表单和五类产品字段合同继续有效。
- 后台左侧导航和普通操作界面使用中文；提交和编辑产品参数的表单字段使用中英文。

## 五、后台信息架构

“产品数据维护”下包含三个二级菜单（2026-09-09 用户确认）：

1. 管理所有产品
2. 销售、包装和价格
3. 总成管理

批量导入产品并入“产品审核与发布”页面。

原“手动新增/编辑产品”的能力迁移到“管理所有产品”的新增和编辑弹窗中。
原“总成兼容关系”更名为“总成管理”。

“产品审核与发布”处理 Excel 导入及旧 Draft 迁移形成的更新请求，不再审核手动新增或编辑的数据。

## 六、领域模型与状态

### 6.1 产品和系列修订

每个产品系列和 SKU 都是一个稳定实体，并拥有多个不可变修订版本。
实体保存一个“当前上线修订”引用，客户页面和新询价读取该修订。

SKU 修订拥有参数、价格金额与币种、包装及图片覆盖引用；系列修订拥有系列属性、
共享代表图和共享销售规则。子体持续继承当前已发布系列数据，不把继承值当作 SKU 自有字段覆盖。
没有正式系列实体的产品继续使用现有商业分组，不强制新增系列参数表单。

一次成功发布只更新本次系列或 SKU 的当前上线修订，不创建或发布整本目录版本。
历史 Catalog Release 继续保留为只读历史数据，但不再作为新维护流程的发布单位。

### 6.2 产品使用状态

产品维护表单只显示三个中文业务状态：

- 上线
- 草稿
- 停用

内部产品发布状态、价格状态、RFQ 资格和供货状态继续由系统联动，不能作为四套独立的人工发布流程。

“草稿”是该产品或 SKU 自己的未上线状态，不代表一份包含完整目录的共享 Draft。

### 6.3 Excel 更新请求状态

Excel 导入产生独立更新请求，其审核状态与目标产品状态分开：

- 更新请求状态：待审核、已批准、已拒绝、已删除；
- 目标产品状态：上线、草稿、停用。

待审核请求可以批准、拒绝或删除；已拒绝请求可以删除。已批准请求只读，不能通过删除撤销生效结果。
校验失败保留待审核并展示问题；校验问题和依赖阻塞是独立标记，不增加产品状态。
修正未批准请求必须保留原导入内容与修正记录；已拒绝或已批准内容再次修改时创建新请求。

拒绝只表示不接受本次更新，并归档该更新请求；不得停用或归档当前上线产品。
删除在普通审核列表中不可见，但仍应保留满足审计要求的最小删除事件。

### 6.4 总成状态

总成关系至少包含两个互不混淆的状态维度：

- 使用状态：启用、停用；
- 数据就绪状态：当前、待更新。

停用不是物理删除。被停用的组合不得进入客户配置器，且不会因为自动更新而被重新启用。

## 七、发布与覆盖规则

### 7.1 手动维护

- 有产品维护权限的人员可以新增、编辑并直接发布自己的修改。
- 不增加独立的发布人或第二人审核权限。
- 手动选择“上线”并成功提交时，新修订立即成为当前上线修订。
- 手动选择“草稿”时，只保存该产品自己的草稿修订，不进入“产品审核与发布”。
- 已有上线修订时，保存新草稿不替换或隐藏当前上线修订；停用必须显式选择“停用”。
- 手动选择“停用”时，停止该产品参与新客户询价和新总成配置，但保留历史引用。

### 7.2 Excel 审核

- Excel 工作簿上传并校验后，转换成结构化的系列和 SKU 更新请求；审核对象不是 Excel 文件本身。
- 每个子体更新请求是不可拆分的审核单元，包含产品参数、SKU 价格、币种、包装长度及其图片引用。
- 不能分别批准同一个 SKU 的参数、价格或图片。
- Excel 导入人可以批准自己导入的条目，不设置职责分离。
- 批准后按目标状态应用该条修订：上线切换当前修订，草稿保存实体自身草稿，停用停止新业务使用；
  不生成完整目录发布。请求批准与目标状态应用在同一事务中成功或失败。

### 7.3 后发布覆盖先发布

同一系列或 SKU 的多次修改，以“发布成功时间”决定当前值：

- 后发布成功的修订覆盖先发布成功的修订；
- Excel 导入时间、表格生成时间和更新请求创建时间不决定覆盖顺序；
- 即使更新请求基于旧数据，只要后来获得批准，也直接成为当前修订；
- 系统不显示过期修改警告，也不要求二次确认；
- 每次发布仍记录来源、操作者、发布时间和修订内容，便于事后追溯。

覆盖单位是该实体的完整自有数据快照，不做逐字段自动合并；系列继承数据及其他实体不在覆盖范围内。
记录提交基线修订和实际被替换的修订，便于区分提交意图与发布效果。
成功发布顺序由服务端事务提交的单调顺序确定，时间戳相同也有确定顺序；
同一请求或命令的幂等重试返回原结果，不能再覆盖其后发布的新修订。
无过期警告不免除参数、引用、身份唯一性、价格、币种、图片和权限校验。

### 7.4 单条原子性和新旧路径隔离

一个条目发布的修订写入、当前状态切换、受影响总成失效和追加审计必须原子完成。
任何失败均不产生半条上线数据。大批量受影响组合可以通过系列版本失效门禁控制，
客户读取和提交时必须即时服从该门禁，不能等待异步计算结束才禁用旧数据。

Ticket 01 起以环境/功能开关隔离新流程：未切换环境继续使用旧完整发布；
启用条目级写入的环境只能有一个发布权威，旧整本发布写入入口必须被服务端阻止。
新读取适配层能读取新条目及冻结的旧 Active 基线、旧历史版本，不能让一个旧目录发布覆盖新条目。
Ticket 05 才正式开放全部新流程并停用生产旧入口；每张票完成不代表立即对生产用户开放。

### 7.5 当前读取与历史依据

一次配置校验、估价或 RFQ 提交读取相互一致的已发布产品、系列和总成版本；并发变化时重读或重试。
新快照保留实际 SKU 修订、继承的系列修订、图片版本、价格与币种、总成生成版本和适用服务规则版本，
或等价的完整不可变依据。旧快照继续按旧 Catalog Release 解析。
打开或提交未提交的询价列表、恢复已保存配置时按当前状态重新校验，原已保存快照和已提交业务记录不改写。

该规则允许旧 Excel 请求在稍后批准时覆盖较新的手动修改，这是本 Spec 明确接受的业务风险。

## 八、管理所有产品

### 8.1 页面区域

页面由筛选区域、功能区域和展示区域组成。

功能区域位于筛选区域右侧，包含：

- 新增
- 编辑
- 删除

### 8.2 筛选

- 产品小类使用多选复选框；
- 可同时选择胶管、压接接头、套筒、过渡接头和快速接头；
- 未选择小类时代表展示全部；
- SKU 查询支持模糊匹配，不要求精确输入。

### 8.3 分组与分页

- 默认展示所有产品小类；
- 有系列的产品以系列作为一级项目；
- 没有系列的产品以 SKU 子体作为一级项目；
- 默认每页展示 20 个一级项目；
- 用户可以切换为每页 50 个一级项目；
- 展开的子体不计入一级项目分页数量；
- 翻页或改变筛选条件时清空当前选择，避免操作不可见条目。

### 8.4 一级展示

系列一级行展示：

- 产品类目；
- 系列名称；
- 系列代表图；
- 展开或收起箭头；
- 系列复选框。

默认不展开子体。点击箭头后展示该系列下的 SKU。

### 8.5 二级展示

每个 SKU 一行，至少展示：

- 产品类目；
- 系列名称；
- SKU；
- 决定 SKU 的关键尺寸；
- 当前零售价格及币种；
- 更多。

胶管展示 Hose ID；压接接头展示 Connection Dash 和 Hose Tail Dash。
套筒、过渡接头和快速接头使用现有数据合同中已经决定 SKU 的关键字段，
不得在本 Spec 中自行增加新的字段或兼容推导规则。

### 8.6 复选框和可用操作

- 选中一个系列：可以编辑系列；满足删除条件时可以删除系列；
- 选中一个 SKU：可以编辑或删除该 SKU；
- 选中多个 SKU：只能执行批量删除；
- 多选系列，或系列与 SKU 混选：禁用编辑和系列删除；
- 系列复选框不代表自动选中其全部子体。

### 8.7 “更多”与编辑

“更多”直接打开该系列或 SKU 的可编辑弹窗，不增加独立只读详情弹窗。

- 打开弹窗不会自动保存；
- 只有点击“提交”才会生效；
- 修改后关闭弹窗时，必须提示是否放弃未保存内容；
- 没有编辑权限的用户只能查看；
- 不要求在提交前增加字段差异预览；
- SKU 修改成功后按所选产品状态直接生效；
- 兼容相关字段发生变化时标记“总成待更新”。

### 8.8 新增菜单

鼠标悬停、键盘聚焦或点击“新增”时，展示产品小类菜单：

- 胶管
- 压接接头
- 套筒
- 过渡接头
- 快速接头

胶管和压接接头继续分为“增加系列”和“增加子体”。选择后打开相应中英文参数弹窗。
套筒、过渡接头和快速接头打开其现有单个产品新增表单。

### 8.9 手动新增系列

- 系列表单继续使用 Spec 9 已确认的中英文字段和必填规则；
- 系列本身不是可销售 SKU，不要求填写产品价格；
- 系列参数校验成功后可直接发布；
- 系列编号创建后不可修改；
- 系列名称和其他允许维护的系列属性可以修改；
- 系列保存共享代表图，子体允许选择覆盖图。

### 8.10 手动新增子体

子体表单继续使用 Spec 9 已确认的中英文字段、必填和选填规则，
并在同一次提交中包含以下 SKU 级商业数据：

- Sales SKU / 销售 SKU：由产品 SKU 自动生成，不重复填写；
- Package Length ft / 包装长度：按产品类型和销售方式校验，不是所有产品必填；
- Retail Unit Price / 零售单价：上线时必填；
- Currency / 币种：上线价格必填，默认 USD，可选择支持的有效币种，至少覆盖 USD、CNY、EUR。

包装长度规则：预包装定长胶管必须提供正的包装长度；按客户长度裁切的胶管可留空，
填写时必须为正数且不替代客户的成品长度。压接接头、套筒、过渡接头和快速接头不要求包装长度，
新提交应隐藏或禁用该字段并拒绝不适用的新值；迁移遇到旧值时保留来源，不静默删除。
现有销售单位与数量输入方式决定包装适用性，前端、手动命令和 Excel 使用相同规则。

每个 SKU 修订只有一组生效的零售金额和币种；换币种必须明确提交金额，系统不自动换算旧金额。
旧 Excel 的 USD 专用价格列只作为 USD 兼容输入；多币种模板使用通用零售单价与币种列，
冲突列值必须报错，不能将非 USD 金额写入或解释为 USD。

以下包装字段继续为选填：

- Units per Sales Pack / 每销售包装数量；
- Net Unit Weight kg / 单个销售单位净重；
- Inner Pack Qty / 内包装数量；
- Master Carton Qty / 每外箱数量；
- Carton Gross Weight kg / 整箱毛重；
- Carton L/W/H cm / 箱长、箱宽、箱高；
- Packing Basis / 装箱依据。

参数、价格和图片作为一个完整提交单元校验。任何必填数据失败时不得发布部分记录。

### 8.11 SKU 删除

界面操作名称保持“删除”，实际行为取决于历史状态：

- 从未上线且没有需要保留的业务、依赖或历史引用的 SKU 可物理删除；
- 已经上线的 SKU 执行停用并从普通产品列表隐藏；
- 历史报价、RFQ、目录版本和审计仍可解析该 SKU；
- 批量删除前显示确认窗口及将被处理的 SKU 数量。

### 8.12 系列删除

- 存在上线子体时禁止删除系列；
- 只有草稿子体且无其他有效引用时允许删除系列，并处理其尚未发布的子体变更请求；
  删除前展示全部影响，不得留下其他请求的悬空依赖，原始来源和删除审计仍保留；
- 只有停用子体时允许删除系列，但系列和停用子体采用隐藏或墓碑记录，不能破坏历史引用；
- 系列及其子体从未上线时允许物理删除；
- 阻止删除时显示造成阻止的上线子体或其他有效引用数量。

## 九、产品审核与发布

### 9.1 范围

“产品审核与发布”审核 Excel 导入及旧 Draft 迁移形成的系列和 SKU 更新请求。
手动新增、编辑或停用不进入该页面。

页面由筛选查询区域、功能区域和展示区域组成。

### 9.2 筛选区域

筛选项包括：

- Excel 导入批次；
- 更新请求状态；
- 目标产品状态；
- 工作表类别；
- 系列；
- SKU 模糊查询。

“系列”选项根据当前工作表类别动态展示对应类目的系列。
页面默认显示待审核的更新请求，而不是默认显示全部上线产品。

原页面顶部的 Active/Draft 切换按钮取消，不再用于选择完整目录 Draft。

### 9.3 展示区域

- 每个系列或 SKU 更新请求一行；
- 每行前有复选框；
- 行尾包含“更多”；
- “更多”展示该请求包含的完整上传或迁移来源数据、价格和图片引用；
- 页面只展示导入或迁移形成的请求，不混入未修改的 Active 产品。

### 9.4 功能区域

功能包括：

- 批准；
- 拒绝；
- 删除。

行为如下：

- 批准：按目标产品状态应用所选请求的新修订；
- 拒绝：归档本次更新请求，不改变当前上线产品；
- 删除：从普通审核视图删除所选请求，不等同于归档产品。

### 9.5 系列和子体依赖

- 尚未发布的系列存在待审核请求时，不能单独批准引用它的子体；
- 同时选中系列和子体时，系统先发布系列，再发布子体；
- 子体校验失败时只阻止该子体，已经成功发布的系列不回滚；
- 批准系列修改时，必须展示所有因继承而受影响的已上线子体；
- 用户确认完整影响范围后发布系列修改；
- 发布系列修改不会自动批准其他新增子体。

同批次每个条目独立提交；展示成功、失败、依赖阻塞的条目与原因，不回滚无关成功条目。
已有上线系列时，子体请求只依赖所引用的有效系列，不自动批准另一个系列修改请求。

### 9.6 Excel 差异与关系来源

- 缺少某个 SKU 行不表示删除或停用；生命周期变化必须显式提交。
- 提供行内的必填空值为校验错误；适用的可选空值表示清空，模板未提供的字段继承基线值后形成完整请求快照。
- 重复且冲突的 SKU 或同系列共享字段在批次中报错，不按行顺序隐式覆盖；完全重复的记录去重并保留来源。
- 未修改的继承数据不形成请求；保存批次、原工作表与行号、基线和原始上传内容以便追溯。
- 工作表 04 的关系与压接源数据另存为待处理关系记录，并展示关联系列/SKU 和处理状态；
  不伪装成 SKU 请求，不随产品批准自动生效。Ticket 04 将其接入总成管理，经有权限人员校验应用；
  三件套源关系保留自身身份与压接信息，经既有规则形成有序 End A/End B 组合，不能从数据中臆造另一端。
- 独立关系变化、无法归属或校验失败的来源必须可见、可修正/重新导入、可审计地处置，不能被整个导入静默丢弃。

## 十、销售、包装和价格

“销售、包装和价格”继续作为“产品数据维护”的第三个二级菜单。

胶管、压接接头、套筒、过渡接头和快速接头的每个产品系列继续共享一套可编辑规则：

- Sales Unit / 销售单位；
- MOQ / 最小起订量；
- Lead Time days / 交期天数；
- Country of Origin / 原产国；
- HS Code / 海关编码；
- Notes / 备注；
- Quantity Input Mode / 数量输入方式；
- Minimum Length per Piece ft / 每根最小长度；
- Length Increment ft / 长度步长；
- Preset Length 1/2/3 ft / 快捷长度 1、2、3；
- Continuous Length Confirmation / 连续长度确认。

共享销售规则仍在该菜单中编辑，不放入系列或子体产品参数区。
入口固定为“产品数据维护 → 销售、包装和价格”，按产品类型和系列选择共享销售规则。
手动提交直接产生该系列的新修订，影响全部继承子体但不覆盖其 SKU 价格、币种、包装和图片覆盖。
在此入口修改 SKU 价格或包装时，同样使用统一条目级发布命令，不继续写共享 Draft。
子体首次新增所必需的 SKU 价格、币种和适用包装数据随子体表单一次提交；
缺少必要系列销售规则时，上线子体应显示该入口并阻止不完整发布。

### 10.1 多币种客户读取与询价

- 产品详情、价格筛选/排序、询价列表、RFQ 和历史展示始终携带金额与币种，不能默认加上 USD 标记。
- 同币种可以计算小计；不同币种分别汇总，不直接相加，也不跨币种按裸金额比较价格。
- 总成的部件、装配服务和保护费用仅在全部输入币种一致时自动估价；任何混币总成保留配置与来源金额，
  进入人工核价，展示需人工核价而非零金额或伪造总价，不阻止有效配置提出人工询价。
- USD 询价门槛和路由仅在完整相关小计可确定为 USD 时自动判断；非 USD 或混币且无法确定者进入人工商业确认，
  不能默认为达标、不达标或套用错误的 DDP/DAP 路由。
- 不自动换汇，不读取实时汇率，不将此 Spec 扩展为支付或正式 PI 的多币种结算重构。

## 十一、总成管理

### 11.1 页面结构

“总成管理”由筛选区域、功能区域和展示区域组成。

### 11.2 筛选区域

筛选项包括：

- End A；
- Hose Series / 胶管系列；
- End B；
- 使用状态（启用/停用）与数据就绪状态（当前/待更新）；
- SKU 模糊查询。

### 11.3 展示区域

- 默认展示全部总成组合；
- 每个总成组合一行；
- 每行前有复选框；
- 行尾包含“更多”；
- “更多”弹窗展示该总成组合的完整部件、状态、来源和审计信息；
- 展示区域标题提供“全选当前页”，不跨页选择；
- 列表上下提供翻页入口，显示当前页、总页数和筛选后的组合总数。

### 11.4 功能区域

功能包括：

- 新增；
- 停用；
- 启用；
- 更新总成数据。

“停用”和“启用”作用于选中的总成组合。
“更新总成数据”不使用当前总成行的复选框决定范围。

### 11.5 手动新增总成关系

手动新增的是一条明确的部件兼容组合关系，包括所需的胶管、End A、End B 和套筒引用，
不是包含长度、Clocking、保护方案或客户价格的成品总成 SKU。

- 手动新增关系标记来源为“手动”；
- 完全相同的组合不允许重复新增；
- 自动更新不得覆盖或删除手动关系；
- 手动关系停用后，自动更新不得将其重新启用；
- 点击“启用”后，该关系才恢复参与配置。

管理对象为稳定的有序 Assembly Component Combination；End A 与 End B 互换且部件不同时是不同组合。
手动关系保留不代表绕过有效产品引用、现有资格和就绪状态校验；仍待更新或部件停用时启用操作不能使其可配置。
相同组合的手动来源优先于自动来源，持续停用排除优先于两者；自动更新不能制造重复组合。

### 11.6 自动更新总成数据

- 系统根据已上线产品及已确认的兼容规则计算受影响系列；
- 只更新从上次成功更新后处于“总成待更新”的系列；
- 不遍历或重写无关系列；
- 点击按钮后先显示将处理的受影响系列；
- 每个系列独立校验和提交；
- 一个系列失败不回滚其他已经成功的系列；
- 页面分别显示成功系列、失败系列及具体原因；
- 成功系列从“待更新”变为“当前”。

每次更新记录输入的相关产品/系列修订和兼容规则版本；提交时核对这些输入仍有效。
运行期间相关 Dash 匹配键、产品可用性或关系再次变化时，旧任务不能将新版本的待更新状态清除；
失败系列继续不可配置，允许幂等重试。纯价格和图片变化不使兼容输入过期，也不要求重建总成。

### 11.7 持续生效的停用规则

总成停用保存为可审计、跨版本持续生效的排除规则，至少记录：

- 被排除的组合身份；
- 操作者；
- 操作时间；
- 可选原因。

自动更新跳过仍然有效的排除规则。启用操作关闭该排除规则，但不删除历史事件。

## 十二、产品发布与总成更新的关系

产品发布和总成更新允许分开执行。

### 12.1 不触发总成更新的修改

以下修改发布后立即用于新客户询价，不要求点击“更新总成数据”：

- 价格；
- 币种；
- 包装；
- 销售规则；
- 交期；
- 备注；
- 图片；
- 压力、温度、扣除量及其他非 Dash 匹配技术参数；
- 不参与兼容判断的普通说明参数。

这些字段沿用现有字段校验和客户读取行为，本 Spec 不新增压力/温度/扣除量的总成重建或额外校验流程。

### 12.2 触发总成更新的修改

以下修改标记相关系列或组合“总成待更新”：

- Hose Dash；
- Hose Tail Dash；
- 套筒 Hose Tail Dash；
- 既有 Dash 匹配规则所需的系列归属、套筒系列和剥胶条件；
- 产品上线、停用或替换造成的兼容集合变化；
- 手动兼容关系或排除规则变化。

字段范围维持 Spec 8 已确认的 Dash 尺寸匹配与系列/套筒/剥胶约束，不新增按压力、温度、扣除量、
接口自由文本或其他技术参数自动推断兼容性的规则。产品生命周期与停用排除仍独立决定能否使用。

SKU 身份不可直接修改。需要改变 SKU 时，必须停用旧 SKU 并新增新 SKU。

### 12.3 客户可见性

- 产品可以先上线，并在普通产品目录或独立产品询价中显示；
- 涉及兼容关系的产品在总成数据更新前显示“总成待更新”；
- 受影响组合在状态恢复为“当前”前不得进入客户总成配置器；
- 不受影响的系列和组合继续可用；
- 新询价读取最新发布价格；
- 历史报价继续保留原产品修订和原价格。

## 十三、图片规则

- 系列保存共享代表图；
- 子体默认继承系列代表图；
- 子体可以选择一张覆盖图；
- 图片替换创建新版本，不重写历史报价或历史目录中使用的图片版本；
- 发布所需图片继续遵守 Spec 8 和 Spec 9 已确认的图片校验规则；
- 本 Spec 不新增多图画廊、强制版权材料或新的图片审批流程。

## 十四、权限与审计

- 产品维护人员可手动新增、编辑并直接发布；
- Excel 导入人可以批准、拒绝或删除自己导入的请求；
- 不增加职责分离或第二人审批；
- 没有编辑权限的用户打开“更多”时只能查看；
- 产品发布、Excel 批准/拒绝/删除、系列与 SKU 删除、总成新增/停用/启用/更新都写入追加式审计事件；
- 审计至少保留操作者、时间、来源、目标记录和允许记录的字段变化；
- 审计事件不能通过后台编辑或删除。

## 十五、数据迁移

已确认的迁移原则：

- 当前 Active Catalog Release 中的系列、SKU、价格、币种、共享销售规则和图片成为各实体修订，
  按原产品生命周期设置当前状态；Active 内的草稿/停用记录不能被错误上线；
- 历史 Catalog Release 保留只读，不改写历史报价和业务快照；
- 新流程启用后不再创建完整 Catalog Release；
- 旧 Draft 和新条目级请求不能同时作为可发布数据源。

- 当前有效兼容关系、总成生成数据、手动来源、排除状态和服务/配置参考规则也必须迁移或建立保留读取映射。

已确认的 Draft 差异迁移规则：

- 清点所有遗留 Draft 及已归档 Draft 的保留范围；只把明确属于未处理维护的数据转换为请求，
  归档历史不自动重新激活，输出纳入与排除清单。
- 按原 Draft 创建基线、Draft 内容、切换时 Active 做三方核对；缺失基线或存在无法确定的冲突时，
  保留原始内容并标记“迁移待审核/需处理”，不能把基线差异擅自当作撤回已发布更新的意图。
- 仅转换真实新增、修改、停用和明确删除意图；未修改的继承行不生成请求。
- 系列属性、共享图和销售规则归系列请求；SKU 参数、价格、币种、包装和覆盖图归 SKU 请求；
  保留系列与子体依赖。关系和压接源数据迁入总成待处理关系记录，不丢弃也不擅自激活。
- 允许迁移不完整 Draft：缺价格、图片或依赖的数据保留为待审核并标注校验问题，修复前不能批准上线。
  请求状态与目标产品草稿状态分别迁移。
- 原 Draft 保留只读及来源追溯，不静默发布、不静默丢弃。删除意图遵守产品历史与引用保护规则。
- 迁移建立稳定来源键与旧记录到新修订/请求的映射，可重跑、可恢复且不重复生成。
- 切换时冻结旧维护写入，校验 Active 和 Draft 版本未在盘点后变化，输出金额/币种、关系、图片和历史读取核对报告。
- 切换前可取消并恢复旧维护；一旦新流程产生写入，恢复不得简单回退旧 Active，必须保留并重放新写入或前向修复。

## 十六、验收标准

### 16.1 条目级发布

- 手动发布一个 SKU 不会发布其他待处理 SKU；
- 批准一个 Excel 条目不需要创建完整目录发布；
- 同一 SKU 后发布成功的修订成为当前值；
- 完整实体覆盖范围、同时间戳顺序、幂等重试和原子失效门禁均有行为测试；
- 旧请求覆盖新修改时不显示警告；
- 每次发布仍可通过审计记录追溯；
- 历史报价和已提交业务快照不发生变化。

### 16.2 产品管理

- 产品小类支持多选；
- 有系列产品按系列折叠展示，无系列产品按 SKU 展示；
- 默认每页 20 个一级项目，可切换 50 个；
- 系列和 SKU 选择规则、编辑限制和删除条件符合本 Spec；
- “更多”直接打开可编辑弹窗；
- 未提交的弹窗修改不会保存；
- 手动新增子体可以在一次提交中完成参数、价格、币种、包装长度和图片校验并上线。
- 多币种价格可保存、读取、按币种汇总并冻结到 RFQ；混币总成走人工核价且不生成伪造总额。
- 包装长度按产品类型与销售方式校验；共享销售规则入口直接发布系列修订且保留 SKU 商业隔离。

### 16.3 Excel 审核

- Excel 工作簿被拆分成独立系列和 SKU 更新请求；
- 产品参数、价格和图片不能被分别批准；
- 拒绝更新不会停用当前产品；
- 未上线系列的子体不能被单独批准；
- 系列和子体同时批准时按依赖顺序处理；
- 系列修改展示全部继承影响，但不自动批准其他新增子体。
- 缺行不删除、可选空值、重复 SKU、关系工作表、不完整请求和批次部分失败具有明确结果。

### 16.4 总成管理

- 管理员可以新增、停用和启用明确的总成组合；
- 手动组合不会被自动更新覆盖；
- 停用组合不会因自动更新重新出现；
- 更新总成数据只处理待更新的受影响系列；
- 单个系列失败不回滚其他成功系列；
- 未完成总成更新的受影响组合不能进入配置器；
- Dash 匹配改变立即失效；压力、温度、扣除量改变不新增重建或额外校验流程；
- 运行期间相关输入再次变化，旧任务不能清除新待更新状态；
- 长度、Clocking和保护方案不参与总成 SKU 生成。

### 16.5 回归与安全

- 现有客户产品目录、配置器、询价列表和后台身份验证继续工作；
- Cost Basis 不出现在客户响应中；
- 图片和历史报价仍解析原版本；
- D1迁移支持本地、预览和生产环境；
- 发布、删除和总成操作具有幂等性和并发测试；
- 自动化测试覆盖手动、Excel、总成和历史快照的完整业务路径。
- 每张功能票即验证权限、审计、失败原子性与适用并发行为；最后一票完成迁移及整体回归。
- 沿用 Worker-backed 管理员操作 → D1 → 客户目录/配置器/询价 → 历史读取的最高业务测试边界；
  在真实本地 D1 验证迁移、重跑、外键和事务，不以模拟仓库测试代替迁移证据。

## 十七、与现有 Spec 和 ADR 的关系

### 17.1 Spec 8

Spec 11取代以下决定：

- 手动和 Excel 修改进入同一个 Catalog Draft；
- 产品和总成必须在一个命令中原子发布；
- 新修改必须形成完整 Catalog Release；
- “更新总成数据”位于“产品审核与发布”。

Spec 8关于兼容键、只更新受影响系列、图片版本、审计、历史快照、
客户选择测量方法以及不生成长度/Clocking/保护方案 SKU 的决定继续有效。

### 17.2 Spec 9

Spec 11取代以下决定：
