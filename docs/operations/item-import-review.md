# 条目级 Excel 导入与审核（Spec 11 Ticket 03 / #84）

条目发布启用后，原「Excel 导入」「产品审核」入口转到
`/admin/catalog/requests`。旧整本发布 POST 仍由 Worker 阻止；生产切换由
Ticket 05 执行。本票不会在生产自动启用条目模式。

下载页面上的条目模板，使用原工作表 01–07。主数据按 SKU 识别，价格表使用
Product Type 与 Base SKU。未提供的列继承导入时完整基线；提供的必填空值报错，
可选空值清空。只想改价时可只上传工作表 07 的产品类型、SKU、通用零售单价和币种列。
缺少 SKU 身份的行保留为批次错误，在批次原始工作簿中可查看，补齐后重新导入。

通用 `Retail Unit Price / 零售单价` 支持 USD、CNY、EUR、CAD、GBP、JPY。
旧 USD 专用列仅允许 USD；两种价格列冲突会阻止审核。客户没有币种选择器或自动换汇。
系列规则仍可在「销售、包装和价格」维护，也可作为工作表 07 的系列共享变更审核。
包装长度沿用手动发布规则：非胶管不适用；胶管按系列销售方式校验。

可选扩展列：`Series Name / 系列名称`、`Series Image Version / 系列图片版本`、
`SKU Image Version / SKU图片版本`。图片值为已保存的媒体版本 ID，可在请求「更多」中
查看并选择；SKU 空图片覆盖继承系列图。私有 Cost Basis 留在原始上传与审计中，
不进入产品发布载荷。

默认仅看待审核请求。系列和 SKU 的完整参数、价格、包装、图片一起批准；
修正需要填写说明且不发布，原始内容和导入基线不变。导入者可自审。
请求状态与产品目标状态独立；已批准请求只读，拒绝或删除请求不会撤销历史发布。
无有效上线系列的子体依赖父系列；批量选择时先处理系列，再逐条处理子体。
失败继续待审核，成功项目不回滚。后批准的完整自有快照覆盖先批准的数据；
已成功请求重试不会重复发布。

## 工作表 04 与 Ticket 04 接口

`catalog_pending_relation_sources` 独立保存关系来源，包含 `id`、`batch_id`、
`source_json`（工作表、行号、原始单元格和字段值）、`issues_json`、`status`、
`disposition_json`、导入人及时间。初始状态为 `pending`。
产品请求的批准、拒绝和删除不会应用或删除这些记录。
Ticket 04 应通过显式总成命令校验引用并写入处置结果和 Admin Audit Event，
保留原始来源；不得物理删除或改写 `source_json`。

迁移 `0056_item_import_review.sql` 添加批次、关系来源及请求版本约束。
批准事务检查请求版本和未解决导入问题，防止修正与批准并发时发布过期内容。
旧 Catalog Release 与历史报价存储保持原样。
