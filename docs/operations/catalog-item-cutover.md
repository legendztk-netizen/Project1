# Spec 11 目录切换

主账号入口：`/admin/catalog/cutover`。顺序为盘点 → 检查报告 → 冻结并核对版本 → 执行切换。安装 0059 只建立协议，不自动切换生产。

盘点记录 Active、全部 Draft、归档/历史 Release、产品、图片、销售规则、金额币种、总成与配置规则的逐表数量和 SHA-256 链校验。产品/关系来源在 `catalog_cutover_records` 按稳定来源键保存完整原内容及目标 ID，报告不包含 Cost Basis 明细。历史 Release 不重新激活。

有创建基线记录的 Draft 使用三方比较；当前 impact analysis 不当作创建基线。缺失创建基线时，差异保存为需确认请求，缺行不直接推断删除。系列与 SKU 请求分开，依赖系列请求保留；缺字段或不满足新校验规则的请求允许留存并修正，不能直接批准。三件套来源单独保留，缺行来源不允许当作新增关系应用。

Active 建立不可变实体修订及来源映射。已有条目修改优先；基线修订不重新规范化旧目录字段，不让有效总成整体待更新。runtime 读取映射保留旧值，后续明确发布的新修订取得该实体的读取权威。旧目录表在切换提交后由数据库触发器禁止写入；客户和后台命令不能绕过。

冻结通过目录写入 epoch 校验盘点一致性，同时禁止旧维护和新条目写入。阶段转换和迁移证据有审计。提交为一个 D1 原子 batch，失败后保持冻结，可按相同 run ID 重试。完成后重复提交不重复生成。

冻结后、正式提交前可取消并恢复原维护状态。正式提交后采用前向修复，不直接回退 Active 指针；恢复备份前必须保存和重放提交后所有产品、请求、总成及客户业务写入。不要将本地备份覆盖已有新增业务的数据库。

导入与审核合并在“产品审核与发布” `/admin/catalog/requests`，原 `/admin/catalog/bulk-import` 跳转到该页导入区。产品数据维护仅保留管理所有产品、销售、包装和价格、总成管理三个子菜单。产品为 `/admin/catalog/products`；总成为 `/admin/catalog/assemblies`。旧导入/审核地址保留跳转。历史数据由原 Release、原 Draft、媒体版本、RFQ/Quote/PI/Order 快照保留，不执行删除或改写。
