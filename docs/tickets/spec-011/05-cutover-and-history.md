## What to build

把当前生产目录完整迁入条目级维护，保留旧 Draft 的真实未处理差异为独立待审核请求，并切换到新产品/审核/总成流程。完成后共享 Draft 和整本发布入口不再接受新写入，当前产品与总成可用，历史目录、RFQ、报价及图片仍按原依据读取，迁移有可核对、可重跑的证据。

## Acceptance criteria

- [x] 切换前清点 Active、所有遗留 Draft、已归档 Draft、系列/SKU、共享销售规则、价格币种、图片、兼容/压接来源、总成、排除规则和服务/配置参考规则；输出纳入/排除范围，不重新激活归档历史。
- [x] Active 内容转换为实体修订并保留原生命周期；Active 内草稿或停用行不得统一上线。现有有效总成/规则迁移或建立保留读取映射，不能因切换默认把所有系列变为待更新或丢失手动/排除来源。
- [x] 旧 Draft 创建基线、Draft 内容与切换时 Active 三方核对，区分真实新增/修改/停用/明确删除意图和未修改继承行，避免把新 Active 的更新误当成需要撤回的 Draft 意图。
- [x] 基线缺失或意图不明的差异保留完整原内容并标注迁移待审核/需处理，不静默自动合并、发布或丢弃；已确认的后发布覆盖规则只在后续明确批准时应用。
- [x] 系列属性、共享图片及销售规则归系列请求；SKU 参数、金额币种、包装及覆盖图归 SKU 请求；保留依赖和原目标产品状态。请求待审核不等于目标产品草稿。
- [x] 缺价格、图片、销售规则或依赖的旧 Draft 保留为可修正待审核请求，带校验错误且无法批准上线；不要求清空遗留 Draft 才完成切换，不丢弃无法适用的新包装规则下的旧值。
- [x] 独立兼容/压接差异迁入总成管理待处理关系源，保留原身份、参数、来源和依赖，不强行归入 SKU 请求或随产品上线自动生效；明确删除意图走保留历史/引用的规则。
- [x] 建立稳定来源键、旧记录到新实体/修订/请求/关系的映射、数量及内容核对报告；相同迁移可重跑/恢复，不重复生成、不篡改原 Draft 来源和历史版本。
- [ ] 在预览环境完成可重复演练；正式切换冻结旧维护写入并核对盘点版本/指纹未变，变化则停止并重新盘点，不允许漏掉切换窗口内写入。（本地部分已验收；远程预览不在本轮范围内，保持未勾选。）
- [x] 统一切换新读写权威，并由服务端停用旧共享 Draft 与整本 Catalog Release 新写入，清除 UI 入口和残留可调用命令；旧 Release 与 Draft 仅保留历史读取/追溯，旧接口不得覆盖新修订。
- [x] 明确恢复策略：新写入前可取消切换并恢复旧维护；新写入后只能在保存/重放新增数据的前提下恢复或前向修复，不能简单回退旧 Active 指针丢弃新数据。
- [x] 新询价即时读取当前条目价格/币种及系列销售规则；按原币种分组汇总，混币总成走人工核价，无法确定 USD 门槛的情况走人工商业确认。保留已有纯 USD 自动路径。
- [x] Dash 匹配/既有匹配约束、生命周期或关系改变即时使相关组合失效，更新完成才恢复；压力、温度、扣除量不新增更新或额外校验，价格变化无需更新总成。
- [x] 旧 Catalog Release、旧 Draft 来源、历史 RFQ/Quote/PI/Order 与图片保持可读且不改写；新业务快照保留实际条目/系列/总成/规则和金额币种依据。未提交询价和保存配置在新操作时重新校验。
- [x] 各票已有权限、审计、原子性与并发验证在最终环境回归，客户无法写后台数据、读取 Cost Basis 或通过旧接口绕过权限；不新增第二人审批。
