## What to build

在旧 Catalog Release 旁建立条目级维护路径，用一个胶管 SKU 贯通管理员手动提交、直接发布、客户读取、新询价、审计和历史快照。完成后可在隔离环境演示：修改一个 SKU 立即生效，其他待处理产品不发布，旧目录和历史报价继续可读。为后续手动维护和 Excel 审核提供相同的发布与读取契约。

## Acceptance criteria

- [x] 系列和 SKU 具有稳定身份、不可变 Product Revision 与当前上线引用；系列拥有属性、共享图片和销售规则，SKU 拥有参数、价格金额/币种、适用包装和图片覆盖引用。子体继承值不得被错误作为 SKU 自有字段覆盖。
- [x] 一个有权限管理员通过最小后台表单发布完整胶管 SKU，客户目录和新询价读取该修订；不会创建整本 Catalog Release 或发布其他条目。
- [x] 建立独立 Product Change Request 的契约：来源、原始内容、实体完整自有数据快照、提交基线、目标状态、依赖和审核状态。手动操作不进入 Excel 队列，但两条入口使用同一验证/发布命令。
- [x] 选择上线立即切换该实体；保存草稿不替换已有上线修订；停用立即阻止新业务使用并保留历史。系列不是销售 SKU，不要求价格；SKU 上线必须满足参数、有效系列/销售规则、价格/币种和图片要求。
- [x] 单条命令原子完成修订、当前状态、受影响总成失效及追加审计；失败无部分可见数据。Excel 请求批准与按目标状态应用修订预留同一原子边界。
- [x] 同实体采用完整自有数据快照覆盖，不逐字段自动合并。服务端成功提交顺序决定后发布覆盖先发布；同时间戳有确定顺序，不按上传时间或请求创建时间排序，不显示旧修改警告。
- [x] 重试同一已成功命令/请求返回原结果，不重新发布、不重复审计、不覆盖后续修订；审计记录来源、操作者、提交基线、实际被替换修订和发布顺序。
- [x] 沿用既有 Dash 匹配及系列/套筒/剥胶约束，产品生命周期和关系变化也控制有效集合。相关发布时同步使受影响系列失效；服务端配置读取、添加询价和提交均拒绝过期组合，不能等 Ticket 04 才补门禁。
- [x] 压力、温度、扣除量不加入总成待更新触发条件，也不新增额外校验流程；价格、币种、包装、图片和销售规则修改不要求重建总成。
- [x] 价格契约保留原金额与币种，默认 USD，允许受支持的非 USD 币种；不存在将非 USD 金额标为 USD 或跨币种裸金额相加的接口。此票用 USD 与至少一个非 USD SKU 修订证明存取及历史快照，完整汇总界面由 Ticket 02交付。
- [x] 当前读取能组合新条目与冻结旧 Active 基线；历史接口仍解析旧 Release。新询价快照记录实际使用的 SKU/系列/图片/金额币种及相关规则版本，不能仅记录无法代表这些条目的旧 Release ID。
- [x] 配置、估价与 RFQ 提交读取一致的版本依据；并发变化时重读/重试。已保存或已提交原始快照不改写，未提交询价重新读取当前数据。
- [x] 环境/功能开关隔离新旧流程。未切换环境保持旧流程可用；启用条目级写入的环境由服务端禁止旧整本发布写入，不能两套发布权威并行覆盖。正式生产开放留到 Ticket 05。
- [x] 所有新命令从首票开始验证真实权限与追加审计，客户响应不含 Cost Basis；不增加第二人审批。
