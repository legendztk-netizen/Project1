## What to build

将“总成兼容关系”改为“总成管理”，让管理员查看、手动新增、停用、启用稳定的有序总成组件组合，并更新由手动产品维护或 Excel 批准产生的受影响系列。旧的受影响组合在更新完成前不可配置，成功系列恢复可用，失败系列保留待更新。

## Acceptance criteria

- [x] 管理对象是有序 Assembly Component Combination：胶管、End A 接头及套筒、End B 接头及套筒；互换不同的 A/B 是不同组合。它不是包含长度、Clocking、保护方案、价格或物理 Assembly Number 的成品 SKU。
- [x] 页面包含筛选、功能和列表区域；按 End A、胶管系列、End B、启用/停用、当前/待更新及 SKU 模糊查询筛选。默认展示全部组合，每行复选框与详情“更多”，表头可全选当前页，列表上下可翻页，并显示当前页、总页数和筛选后组合总数（按用户后续确认）。
- [x] 新增、停用、启用作用于明确组合；“更新总成数据”范围由系统计算的待更新系列决定，不能按复选框缩小，也不遍历/重写无关系列。
- [x] 详情展示完整部件、稳定身份、使用状态、数据就绪状态、手动/自动/导入来源、生成依据和审计；既有三件套关系与完整 A/B 组合明确区分。
- [x] 手动新增验证部件引用、既有资格与重复身份，保存手动来源；自动更新不覆盖/删除手动关系。保留不等于无条件有效：部件停用、引用失效或系列待更新时仍不得进入配置器。
- [x] 组合停用保存跨修订持久排除规则，以稳定有序身份关联，记录操作者/时间/原因。自动重建不能复活停用组合；启用结束当前排除但保留历史，且不能绕过未就绪或无效部件。
- [x] 手动来源优先于自动来源，停用排除优先于两者；同组合不重复生成。自动过期组合从当前生成结果移除，但历史引用及手动关系/排除记录保留。
- [x] 接入 Ticket 03 的工作表 04 待处理关系源和迁移来源；管理员可查看、校验应用或明确拒绝/删除并留痕。保留三件套关系及压接参数原义，经既有规则形成 A/B 组合，不臆造另一端，不将来源当作生产已验证证据。
- [x] 关系依赖的产品未上线或无效时不能应用；应用后记录来源、所用产品修订及受影响系列。只有关系被明确处理并完成相应更新后，相关新组合才可配置。
- [x] 点击更新先展示完整受影响系列；逐系列独立校验并原子提交生成结果及就绪状态，一个失败不回滚其他成功系列，分别展示结果与原因，失败系列继续不可配置。
- [x] 受影响集合覆盖新旧依赖、共享接头/套筒和移除产品；使用现有 Hose Dash/Hose Tail Dash 与系列/套筒/剥胶匹配及生命周期约束，不增加压力、温度、扣除量的更新或额外校验流程。
- [x] 更新记录相关产品/系列修订和兼容输入版本，提交时确认仍有效。更新期间相关输入再次改变，旧计算结果不得清除新的待更新标记；允许幂等重试，不受无关价格/图片发布影响。
- [x] 从 Ticket 02 手动发布及 Ticket 03 批准到即时门禁、更新、恢复客户配置的路径均可演示。客户直接调用添加或提交接口也不能使用停用/过期组合。
- [x] 价格按客户当前配置时的最新原币种输入读取；价格/币种改变不强制总成重建，混币估价继续走人工核价。已保存配置恢复时重新校验，历史 RFQ/报价、图片和原始配置快照不改写。
- [x] 所有关系/排除/更新命令验证权限并追加审计；失败不能产生半个可用系列或错误启用，客户数据不含 Cost Basis。
