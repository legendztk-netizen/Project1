## What to build

把 Excel 工作簿转换为独立系列/SKU 变更请求，管理员能查看完整变更、筛选并批量批准、拒绝或删除。批准按请求目标状态直接生效，一个条目的参数/价格/图片不可拆开审核，导入人可以审核自己提交的数据。

## Acceptance criteria

- [x] 导入覆盖现有五类产品与工作表 01–07，保留批次、工作表/行号、原始内容和基线；成功导入不直接改变客户数据，不创建共享 Catalog Draft。
- [x] 每个系列/SKU 形成独立请求；系列属性、共享图片、销售规则归系列，SKU 参数、价格金额/币种、适用包装及图片覆盖归 SKU。未修改继承内容不生成请求，参数、价格和图片不可分别批准。
- [x] 缺 SKU 行不删除产品；提供行内必填空值报错，适用可选空值表示清空，模板未提供字段继承基线后形成完整快照。冲突重复 SKU 或同系列共享字段报错，完全重复记录去重并保留来源。
- [x] 多币种模板使用通用零售单价与币种列，允许受支持非 USD 币种；旧 USD 专用列仅兼容 USD，冲突列值报错，不把原币金额当 USD。包装长度与手动入口采用相同的类型/销售方式规则。
- [x] 保留可修正的不完整请求及校验问题，不能批准上线；修正保留原导入内容及修正审计。关联记录错误不得造成未明确的部分数据上线。
- [x] 审核页默认待审核请求，取消整本 Active/Draft 切换。支持批次、请求状态、目标产品状态、工作表类别、动态系列和 SKU 模糊筛选；每条请求有复选框及展示全部上传数据/价格/图片的“更多”。
- [x] 请求状态为待审核/已批准/已拒绝/已删除，与目标产品上线/草稿/停用分开。待审核可批准/拒绝/删除，拒绝不改变当前产品；已批准请求只读，删除不是撤销发布；校验失败保持待审核并说明原因。
- [x] 批准调用 Ticket 01 统一命令，按目标状态原子应用修订并记录批准；目标草稿不替换已有上线修订，目标停用阻止新业务，目标上线直接切换，无整本发布操作。
- [x] 导入人可自审，不增加第二人审核；未经授权的读取/操作被拒绝，Cost Basis 不泄露到客户。
- [x] 没有有效已上线系列时，不能单独批准依赖子体；同时选中系列与子体先系列后子体。已有有效系列时，不强制批准无关系列修改请求；发布系列修改展示全部继承影响，但不自动批准其他新增子体。
- [x] 批量逐条独立提交，明确展示成功/失败/依赖阻塞及原因；子体失败不回滚成功系列，父系列失败不发布依赖子体，无关请求可成功；同一已成功请求重试无重复发布。
- [x] 同实体后发布的完整自有数据快照覆盖先发布，不按 Excel 年龄判断、不警告、不自动逐字段合并；批准旧请求后再次重试不能覆盖后续新发布。
- [x] 发布涉及 Dash 匹配、现有系列/套筒/剥胶或产品可用性时即时失效受影响总成；纯价格、币种、图片及压力/温度/扣除量不新增重建或额外校验流程。
- [x] 工作表 04 的兼容/压接源关系单独保留为可查询的待处理关系记录，展示引用、来源和错误，不能伪装成 SKU 请求、随产品批准隐式生效或静默丢弃；为 Ticket 04 提供接入总成管理的契约。
- [x] 审核页明确显示批次中尚未处理的关系记录；拒绝/删除产品请求不得默默删除其他待处理来源，需保留可追溯处置结果。
