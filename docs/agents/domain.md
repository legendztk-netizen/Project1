# Domain Documentation

This repository uses a single domain context.

- Read the root `CONTEXT.md` before creating a Spec, Ticket, implementation, or
  review. It is the canonical glossary and its preferred terms must be used.
- Product and workflow requirements live under `docs/product/`.
- Project-level product direction lives under `docs/prd/`.
- Bounded implementation Specs live under `docs/specs/`.
- Architecture decisions live under `docs/adr/` and apply across all Specs
  unless a later accepted ADR supersedes them.
- Do not copy definitions into feature documents when linking to the canonical
  term is sufficient. A changed domain meaning must update `CONTEXT.md` first.
